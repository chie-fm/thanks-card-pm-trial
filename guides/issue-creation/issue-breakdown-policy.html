Issue 細分化実装方針

親 Issue を Copilot が実装できる粒度の Sub-issue へ分解する方針と手順を説明します。

🎯 基本方針

Issue の細分化も Copilot に任せる
親 Issue に書かれた要件をそのまま Copilot に渡すのではなく、Copilot が実装できる粒度まで Sub-issue を分解してから開発を始めます。

ジェネレーターに技術スタック・実装アプローチ・テスト方針を入力することで、Copilot が各 Sub-issue の本文（目的・実装手順・参照ファイル・完了条件）を自動生成します。

生成された Sub-issue は GitHub CLI コマンドとして出力されるため、コピペするだけで Issue を一括登録できます。

📋 作業フロー

1
ジェネレーターで入力
親 Issue 番号・目的・背景・技術スタック・実装アプローチ・テスト方針などを入力します。
フォームの内容はブラウザに自動保存されるため、途中で閉じても復元できます。
issue-breakdown-generator.html
2
MD 本文を生成・保存
「生成」ボタンを押すと、Copilot への実行用 MD 本文が出力されます。
提案ファイル名（例: issue-breakdown-issue-8-20260513.md）でコピーし、新しい空ファイルに貼り付けて保存します。
3
Copilot に実行を依頼
生成された実行指示（例: issue-breakdown-issue-8-20260513.md を読み込んで実行して）を Copilot チャットに貼り付けて送信します。
Copilot が Sub-issue の一覧と GitHub CLI コマンドを提案します。
4
提案を確認・実行
Copilot が出力した Sub-issue 案を確認し、必要に応じて修正してから「実行して」と送信します。
CLI コマンドが走り、GitHub に Sub-issue が一括登録されます。
5
差分管理・見直し（必要時）
Sub-issue を追加・変更・Close する場合は、ジェネレーターの「差分管理モード」を使います。
現在の Sub-issue 一覧と新しい期待リストを入力すると、Copilot が差分を分析して Close コマンド付きで出力します。

📝 入力項目一覧

*必須 の項目は Copilot が Sub-issue 本文を生成するために必要な情報です。
不足があると「要確認」として明示されます。

項目 必須/任意 説明
親 Issue 番号 必須 細分化する対象の親 Issue 番号
目的 必須 この Issue で達成したいこと（Copilot が方向性を判断）
背景・課題 必須 なぜこの Issue が必要か（Copilot が優先度を判断）
対象範囲（やること） 必須 実装する機能・画面・API の範囲
完了条件 必須 Done になる具体的な基準（テスト通過・動作確認など）
技術スタック 必須 使用言語・フレームワーク・DB など（Sub-issue 本文に含める）
実装アプローチ 必須 実装の方針・設計の考え方（Copilot が分割粒度を決める根拠）
テスト方針 必須 単体/E2E/手動など、テスト種別と対象（Sub-issue 本文に含める）
細分化の観点 必須 機能別・フェーズ別・優先度別・担当者別など
対象外（やらないこと） 任意 スコープ外の明示（あると Copilot が余計な Sub-issue を作らない）
制約・注意点 任意 期限・変更禁止事項・依存関係など
参照ファイル・関連コード 任意 実装に関連するファイルパス（Copilot が参照できる）

📄 Sub-issue 本文フォーマット

Copilot が生成する各 Sub-issue の本文構成
  • 親 Issue 参照 — 例: 親 Issue: #8
  • 目的 — このタスクで達成すること（1〜2文）
  • 実装アプローチ — 技術スタック＋具体的な実装手順
  • 参照ファイル・コード — 変更・参照するファイルパスのリスト
  • テスト方針 — 何をどうテストするかを明記
  • 完了条件 — Done の具体的な基準

⚙️ ジェネレーターを開く

フォームに入力するだけで Copilot 実行用の MD 本文が生成されます。
入力内容はブラウザに自動保存されます。
